# 04 - 发版流程

仓库唯一的核心工作流：替换 Framework 产物 → 改版本号 → 校验 → 打 tag → 发布到 CocoaPods trunk。

## 前置准备

1. 将新构建的 6 个 Framework 替换到 `TKUISDK_iOS/Frameworks/`（资源有变更时同步更新 `Bundles/TKResources.bundle`）。
2. 在 Example 目录执行 `pod install`，编译运行验证集成。
3. 修改 `TKUISDK_iOS.podspec` 的 `s.version`（如 `4.18.5.5`）。

## 发布步骤

```bash
# 1. 提交代码（含 podspec 版本号变更）
git add .
git commit -m "release x.x.x.x"
git push

# 2. 本地校验
pod lib lint TKUISDK_iOS.podspec --allow-warnings --skip-import-validation

# 3. 打 tag（必须与 s.version 完全一致）并推送
git tag x.x.x.x
git push --tags

# 4. 远程校验（真实拉取 GitHub 上的 tag 验证）
pod spec lint TKUISDK_iOS.podspec --allow-warnings

# 5. 发布到 CocoaPods trunk
pod trunk push TKUISDK_iOS.podspec --allow-warnings
```

## 注意事项

- **顺序不可颠倒**：必须先 push 版本号变更，再打 tag；tag 与 `s.version` 不一致会导致第 4 步远程校验失败。
- **网络代理**：push / lint 网络不通时，终端临时走代理：

  ```bash
  export http_proxy=http://127.0.0.1:7890
  export https_proxy=http://127.0.0.1:7890
  ```

- **trunk 生效延迟**：发布后客户搜不到新版本时，可临时按 git 源接入（建议带 `:tag` 锁定版本）：

  ```ruby
  pod 'TKUISDK_iOS', :git => 'https://github.com/Talk-Cloud/TKUISDK_iOS.git', :tag => 'x.x.x.x'
  ```

- **首次发布**：需先注册 trunk 会话 `pod trunk register <email> '<name>'`，点击邮件链接确认后再执行 push。
- `s.description` 目前为 TODO 占位，lint 会产生警告（`--allow-warnings` 可通过）。
